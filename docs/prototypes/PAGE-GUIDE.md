> **版本**:v0.8(2026-08-03)

## 1. 原型总览

### 1.1 一句话定位

10 个原型围绕"**对话即任务 + 模板即复用 + 能力即配置**"三条主线,验证领导在评审会上提出的三大问题:对话如何落地为值守任务、团队能力如何跨地域复刻、新平台如何零代码接入。

**全面对标 WorkBuddy v5.3.8 侧栏骨架**(只删了助理/项目两个不需要的入口),左侧栏任何页面打开 100% 完全一致,只有右侧内容区在变。

### 1.2 信息架构:完全固定侧栏

所有 10 个原型共用同一套**完全固定**的侧栏,按"用户分层 + 使用频率"自上而下排列:

```
┌─ 侧栏 240px · 完全固定 ────────────────────────────┐
│  [Logo] UniEcoClaw · 数智环保                            │
│  ──────────────────────────────────────────────      │
│  🌱 新建任务    【主按钮,点击=跳对话】               │ ← WorkBuddy 最顶部按钮
│  ──────────────────────────────────────────────      │
│  ⏰ 自动化                  普通用户·主战场           │ ← 原"值守任务"改名
│  📋 任务模板库              业务用户·克隆/分享/导入    │ ← 原"常用任务"改名,强调配方
│  🧰 能力·技能·连接器        开发者·广义工具箱         │ ← 原"能力与平台"
│       └ 右侧二级tab: 平台 / 能力 / Skill / 连接器    │
│  ⋮ 更多                     (日志/用量/性能折叠)      │
│  ──────────────────────────────────────────────      │
│  最近对话 (5)                                        │ ← 全页面通用,不随切页变化
│   新对话 / 平顶山值守 / 运行上下文×3 + 查看更多(2)  │
│  ──────────────────────────────────────────────      │
│  [A] Acerola    🔔通知   ⚙️设置                      │
└──────────────────────────────────────────────────────┘
```

**active 规则(只有 4 顶级入口里的那一项会高亮)**:
- 对话页:4 顶级入口都不 active,因为顶部「🌱 新建任务」本身已是视觉焦点
- 自动化 3 页:⏰ 自动化 active
- 任务模板库 3 页:📋 任务模板库 active
- 能力·技能·连接器 2 页:🧰 能力·技能·连接器 active

### 1.3 统一规范

## 2. 对话入口(2 个)

### 2.1 `duty-chat.html` — 对话主页

**定位**:所有人最常用的入口,"对话即任务"的起点。

**核心功能**:
- 空态 hero:大标题"今天想查什么?" + 场景 tab + 能力 chips
- 能力 chips:从已接入平台动态派生(浓度排名/一张图/小时播报/监测数据),点击即预填提问
- 斜杠指令:`/` 唤出指令浮层(创建任务/切换模型/查看任务)
- 对话流:用户提问 → AI 回答 → 识别到周期性需求时,在末条消息下方弹出"任务草稿卡"
- 草稿卡:展示 AI 抽取的任务名/能力/调度/推送,提供"直接确认(跳过向导)"和"继续修改"两个出口

**关键交互**:
1. 点能力 chip → 输入框预填"用浓度排名查平顶山 PM2.5"
2. 发送 → AI 回答 + 草稿卡出现
3. 点"直接确认" → 跳过向导直接生成 Job;或点"继续修改" → 在对话里调整(如"改成每小时")

**设计要点**:
- **显式按钮而非 AI 主动派发**:领导反复强调"用户必须能控制",AI 不会偷偷把需求变成任务,必须用户点按钮才创建
- 能力 chips 不再硬编码,从 `usePlatformsStore` 派生(M1 代码改造点)

**回应领导关切**:对话如何落地为值守任务 → 本页演示完整闭环。

---

### 2.2 `chat-create-task.html` — 对话→任务闭环演示

**定位**:完整演示"用户提问 → AI 抽取草稿 → 确认创建"的全流程,带自动重放。

**核心功能**:
- 演示横幅:顶部提示"这是闭环演示",带"重新播放"按钮
- 自动演绎:进入页面后自动播放用户提问 → AI 思考 → 草稿卡生成 → 确认创建 → 成功链接
- 草稿卡网格:4 字段(任务名/能力/调度/推送)结构化展示,每项可"调整配置"
- 创建成功:草稿卡变绿,出现"查看任务 →"链接跳转 duty-task-detail

**关键交互**:
1. 页面加载自动播放演示(也可点"重新播放")
2. 演示中点"调整配置" → 展开字段编辑
3. 点"确认创建" → 草稿卡转绿 + 出现任务链接

**设计要点**:
- 与 `duty-chat.html` 共享底座公共样式(chat-shell/hero/draft-card/composer),去重后只在 `duty-proto.css` 维护一份
- 本页是"演示用",`duty-chat.html` 是"日常用",二者互补

**回应领导关切**:直观看到"对话即任务"不是概念,是可演示的闭环。

## 3. 自动化入口(原"值守任务",3 个)

> **命名说明**:原"任务/值守任务"改名"自动化"——更准确表达"按 cron 自动跑任务"的语义,和 WorkBuddy 对齐。原 4 个页面合并为 3 个。

### 3.1 `duty-tasks.html` — 自动化主控(2 个二级 tab)

**定位**:普通用户管理自动化任务的主战场。顶部 **2 个二级 seg-btn**:① 定时任务 ② 运行记录。

**核心功能(Tab 1:定时任务)**:
- 视图切换:列表 ↔ 看板(`.seg-switch`)
- 列表视图:任务卡片网格,展示任务名/状态/调度/推送/下次运行/最近结果
- 看板视图:3 列(运行中 / 已暂停 / 已结束),紧凑任务卡含进度条
- 筛选:状态 pill(运行中/已暂停/已结束/异常)+ 搜索框
- 顶部 4 统计卡:运行中 / 已暂停 / 已结束 / 异常

**核心功能(Tab 2:运行记录)**:
- 4 统计卡:总运行 / 成功 / 失败 / 成功率(带趋势涨跌)
- 工具条:按时间(今天/昨天/近 7 天)+ 按状态(全部/成功/失败)+ 按任务筛选
- 报告列表:时间 / 任务名 / 状态 / 耗时 / 截图数据标记 / 触发方式
- 展开详情:运行截图 + 数据表 + 错误日志(失败任务高亮红色背景)

**关键交互**:
1. 点顶部「定时任务 / 运行记录」切换二级 tab(支持 `#tab=runlog` 锚点直达)
2. 列表↔看板切换;点状态 pill 筛选
3. 点任务卡片 → 跳转 `duty-task-detail.html`
4. 点"+ 创建任务" → 跳转 `duty-create.html`
5. 运行记录 tab:点报告行展开详情(箭头旋转),失败任务看完整错误堆栈

**设计要点**:
- 已合并 2 个删除页面的内容:看板视图来自 `duty-workbench.html`,运行记录来自 `duty-run-report.html`
- 任务数据 JS 驱动,7 条 mock 任务覆盖四种状态;报告数据与任务数据对齐

**回应领导关切**:任务运行状态一目了然,异常任务(凭证失效)高亮可见;运行记录统一在一个 tab,不用跳页面。

---

### 3.2 `duty-task-detail.html` — 任务详情

**定位**:单个自动化任务的详情页。

**核心功能**:
- 详情头:任务名 + 状态 + 城市 + cron + 下次运行 + 推送渠道 + 成功率 + 运行次数
- 操作区:立即运行 / 暂停 / 编辑 / **保存为任务模板** / 删除
- 侧栏任务树:a-f 任务列表,点击切换详情
- 历史报告:近期运行记录列表,可展开看截图与日志

**关键交互**:
1. 点侧栏任务树切换不同任务详情
2. 点"立即运行"触发即时执行
3. 点"保存为任务模板" → 跳转 `template-editor.html` 预填(串起自动化→任务模板库的关键出口)
4. 展开历史报告看截图/数据表/错误日志
5. 点历史报告里的「查看全局运行记录」→ `duty-tasks.html#tab=runlog`

**设计要点**:
- "保存为任务模板"是自动化→任务模板库的关键出口,串联两个顶级入口
- 异常任务(如"污染源超标异常监控")展示完整错误信息(钉钉 Webhook 失效)

---

### 3.3 `duty-create.html` — 创建自动化向导

**定位**:3 步创建自动化任务,支持从对话/模板预填。

**核心功能**:
- 步骤导航:步骤 1 选能力 → 步骤 2 设推送 → 步骤 3 确认(`.step-item` 带连接线)
- 步骤 1:能力选择(浓度排名/一张图/小时播报/监测数据),每项可展开配置参数
- 步骤 2:推送渠道(企业微信/飞书/钉钉)+ 调度预设(每小时/每天/每周/自定义 cron)
- 步骤 3:确认任务名 + 能力清单 + 调度 + 推送,提交生成 Job

**关键交互**:
1. 点能力卡片展开参数表单,用 `.segmented` 分段切换
2. "下一步"推进,"取消"返回 duty-tasks
3. 步骤 3 点"创建" → 生成 Job 跳转详情

**设计要点**:
- 复用 `CreateTask.vue` 的 3 步骨架(已上线验证)
- 支持预填:从对话草稿卡或任务模板进入时,字段自动填充
- M3 改造点:能力列表从硬编码改为 API 拉取

**回应领导关切**:新平台接入后,能力自动出现在步骤 1,无需改代码。

## 4. 任务模板库入口(原"常用任务",3 个)

> **命名说明**:原"常用任务"改名"任务模板库"——v1 叫"常用任务"用户以为是"待办清单",实际是"团队配方仓库"。改完名业务用户一眼就懂:这里是别人做好的配方,我拿来改改就用。

### 4.1 `templates-library.html` — 模板库主页

**定位**:业务用户主战场,团队经验复用的核心入口。

**核心功能**:
- 两列布局(新:原侧栏分组搬到右内容区):左分组列表 / 右卡片网格
- 左分组:分组 5 项(全部模板/系统预置/我的模板/已收藏/日报周报)+ 标签 4 项
- 右卡片网格:每张卡展示模板名 / 描述 / 标签 / 作者 / 使用次数 / 克隆次数
- 3 Tab 分类:全部 / 系统预置 / 我的(已删除"团队"Tab,按用户要求)
- 顶部 3 统计卡 + 筛选 pill + 搜索;右上角「分享/导入」跳 template-share,「新建模板」跳 template-editor
- 卡片操作:克隆 / 分享 / 创建自动化任务

**关键交互**:
1. 左分组点选 → 右网格实时筛选;3 Tab 切换分类
2. 点卡片 → 进入 `template-editor.html` 查看/编辑
3. 点"克隆" → 派生新模板;点"分享" → 进入 `template-share.html`
4. 点"创建任务" → 跳转 `duty-create.html` 预填

**设计要点**:
- 原侧栏的分组/标签搬到右侧内容区,左侧栏统一为固定 4 顶级入口(所有页面一致)
- "团队"Tab 已删(用户决策:没用)

**回应领导关切**:平顶山团队换到郑州,克隆"郑州周报"模板改个收件人即可上线——跨地域复刻能力。

---

### 4.2 `template-editor.html` — 模板编辑器

**定位**:编辑任务模板的 4 步配置。

**核心功能**:
- 4 步配置:信息 / 能力 / 交付 / 高级
- 信息步:模板名 / 描述 / 标签 / 分类(系统/我的)
- 能力步:能力逐项展开配置(同 duty-create 步骤 1,但更完整)
- 交付步:推送渠道 + 调度预设 + 角色基底提示词
- 高级步:重试策略 / 超时 / 优先级等

**关键交互**:
1. 4 步表单填写,能力项可折叠展开
2. "保存模板" → 回 templates-library
3. "保存并创建任务" → 跳 duty-create 预填该模板

**设计要点**:
- 与 `duty-create.html` 的能力配置段共享交互模式(分段切换、折叠展开)
- 角色基底提示词:为 AI 执行提供上下文(如"你是空气质量分析师")

---

### 4.3 `template-share.html` — 模板分享 / 导入

**定位**:模板跨设备、跨团队流转(tar.gz 离线模式)。

**核心功能**:
- 导出区:勾选导出项(模板配置 / 能力定义 / 凭据占位 / 角色提示词),生成 tar.gz
- 导入区:拖拽 tar.gz 文件,自动解析
- 冲突提示:同名模板存在时,提示"覆盖 / 保留两者 / 跳过"

**关键交互**:
1. 勾选导出项 → 点"导出"下载 tar.gz
2. 拖拽文件到导入区 → 自动解析预览
3. 冲突时选处理方式

**设计要点**:
- tar.gz 离线模式:无需服务器即可跨团队分享(M4 公开市场前的过渡方案)
- 凭据不导出(安全):只导出占位符,接收方填自己的凭据

**回应领导关切**:平顶山团队能力复刻到郑州,导出 tar.gz 发给郑州团队导入即可。

## 5. 能力·技能·连接器入口(原"能力与平台",2 个)

> **定位**:开发者的"广义工具箱"。原 `duty-capabilities` + `platforms-hub` 合并为一个入口,顶部 **4 个二级 tab**(平台 / 能力 / Skill / 连接器),一个页面装完所有高级概念,避免用户分不清。普通用户日常用不到,首屏有 onboarding 引导。

### 5.1 `duty-capabilities.html` — 广义工具箱主控(4 个二级 tab)

**定位**:工具箱的主控页面,顶部 4 个二级 seg-btn 切换 4 类内容。支持 `#tab=platforms` 等 hash 直达。

**Tab 1:平台(原 platforms-hub.html 内容)**:
- 3 统计卡:平台总数 / 在线 / 能力总数
- 平台列表 3 张:数智大气「内置锁定不可删」/ 河南省厅 / 国控站
- 状态徽章:在线 / 离线;类型:系统自有 / 外部 / 政务内网
- 「+ 添加平台」按钮 → 跳 `platform-onboarding.html`

**Tab 2:能力**:
- onboarding 琥珀卡片:"这是工具箱,日常用不到,想扩展能力再来看"
- 4 类能力网格:数据采集 / 数据分析 / 预警 / 办公
- 每张能力卡:名称 / 描述 / 来源平台 + 三个操作:测试 / 详情 / 创建自动化任务

**Tab 3:Skill**:
- onboarding 占位卡 + 「打开 Skill 管理器(示意)」按钮
- 说明:AI Agent 的可复用技能(如数据采集、报告生成)

**Tab 4:连接器(MCP)**:
- onboarding 占位卡 + 「打开 MCP 管理器(示意)」按钮
- 说明:Model Context Protocol,连接外部工具和数据源的标准接口

**关键交互**:
1. 点顶部 4 个 seg-btn 切换 tab(支持 hash 直达)
2. 平台 tab:点「添加平台」→ 4 步接入向导;点平台卡查看详情
3. 能力 tab:点「测试」验证能力;点「创建任务」→ 跳 duty-create 预填
4. Skill / 连接器 tab:点管理器按钮(示意)

**设计要点**:
- 一个入口装完 4 个概念(平台/能力/Skill/连接器),用户不用再记哪个在哪个页面
- 内置平台(数智大气)锁定不可删,防止误删底座能力
- 首屏默认打开「平台」tab,因为用户从平台 onboarding 完成后会跳回这里

**回应领导关切**:Skill / MCP 从"设置"二级菜单提级到顶级入口下的 tab,可发现性大幅提升;新平台接入后,能力自动出现在「能力」tab 和 CreateTask 向导。

---

### 5.2 `platform-onboarding.html` — 平台接入向导

**定位**:4 步接入新数据平台,零代码。

**核心功能**:
- 步骤 1 基本信息:平台名 / 类型(系统自有/外部/自定义/政务内网)
- 步骤 2 网址与凭据:接口地址 / 操作提示词 / 访问方式(Web/API)/ 账号密码显示·隐藏
- 步骤 3 功能 prompt:本平台独有功能清单(每条 name + prompt),动态增删
- 步骤 4 技能挂载:从现有 Skill 库勾选要挂载的技能

**关键交互**:
1. 4 步向导推进,"下一步" / "保存草稿" / "取消"
2. 步骤 2 密码可"显示/隐藏"
3. 步骤 3 动态增删功能项(+ 添加功能 / × 删除)
4. 步骤 4 勾选技能
5. 完成 → 跳转 `duty-capabilities.html#tab=platforms`,平台列表新增

**设计要点**:
- 4 步向导而非填表:向导是用户视角,填表是工程师视角
- 复用 `TemplateWizard.vue` 的 4 步骨架(值守任务已验证)
- 接入后零代码:`CreateTask` 自动拉取新平台功能列表

**回应领导关切**:新能力怎么接进来 → 4 步向导,接入后能力自动可用,无需改核心代码。

### 6.3 关键设计决策速查

1. **"常用任务"改名"任务模板库"** — 纠正语义错配,业务用户一眼懂是"配方仓库"
2. **"任务"改名"自动化"** — 准确表达 cron 定时执行语义,对齐 WorkBuddy
3. **侧栏 100% 固定** — 对标 WorkBuddy,任何页面侧栏一致,只有右侧内容区变化
4. **对话→任务走显式按钮** — 用户必须能控制,AI 不主动派发
5. **平台/能力/Skill/连接器合并** — 一个入口 4 个 tab,装完广义工具箱,用户不用到处找
6. **删除 3 个独立页** — duty-workbench(看板并入 tasks)、duty-run-report(运行记录并入 tasks)、platforms-hub(平台并入 capabilities)
